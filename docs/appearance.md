# Appearance and interface sounds

`src/styles/appearance.css` holds the shared glass treatments and dark-mode overrides. It is imported by the main stylesheet. Dark surfaces use a near-black canvas, translucent neutral panels and restrained versions of the existing accent colours. Light mode uses the same accent hues at reduced opacity, translucent white panels, a visible reflective sheen and bright inset edges. Each panel has a soft haze matching its own colour; white panels use white haze. Geometry and text colours stay unchanged. Reduced-transparency and increased-contrast preferences switch panels to solid fills.

`src/styles/glassControls.css` supplies the shared button sheen, delicate rim and short hover/press feedback in both themes. The mock-test CTA uses the same compact pill class as practice Continue buttons, avoiding a competing motion shadow animation. Unlock choices are content-sized chips in the corresponding practice colours. The circular Settings control and Sign In share a height (36 px for a pointer, 44 px for touch). Settings and account panels use translucent materials with stronger blur for legibility. Recommendations use the same surface treatment as the surrounding dashboard. Card haze colours are resolved on each card: yellow, lavender, peach, blue, or white to match its surface. Neutral canvases avoid tinting every halo purple. A shared `--haze-strength: 70%` scales all card and button halos down by 30%, including hover states, without changing their colours or the frosted surfaces. Recommendation rails reserve 32 pixels of paint room on every side so the haze fades without being clipped. Spelling score actions have a separate content gap and their card no longer stretches to the adjacent bank's height.

`index.html` reads the saved `omniprep_theme` before application modules load. Its small critical style keeps the initial document canvas dark while CSS and authentication load. Both authentication and page-transition loaders use the theme's canvas colour. The app updates the browser theme colour when appearance changes.

Button sounds are synthesized locally with Web Audio at a maximum gain of 0.018 and a 45 ms duration. Settings → Button sounds toggles the device preference (`cognition_interface_sounds`); it is enabled by default and works without signing in. There is no separate navigation sound button. Click feedback is suppressed during speech, media playback and microphone recording, and on pronunciation/record-start controls. Sounds never use or cancel the speech synthesizer.

`npm run test:appearance:browser` checks spelling comparison, preserved light accent hues with translucent fills, dark text contrast, mobile overflow, solid high-contrast fallbacks and sound/mute behaviour. `npm run test:loading:browser` delays application/auth loading to check the initial canvas and real loaders in both themes. Both use the same Playwright environment variables as the spelling browser tests; Web Audio is instrumented, so subjective listening remains part of local review.
